# cowa 是信使，不是把关人

cowa 不对硬件参数的真伪下判断。这条立场有三张脸：

- **照抄**：WMI 给什么就显示什么。`Win32_VideoController.AdapterRAM` 是 32 位字段，显存超过 4GB 时会给出溢出的垃圾数（`4095MB`）——**cowa 照显**，不隐藏、不替换、不加"不可信"脚注。
- **未知**：读不到就写 `未知`，不猜、不用别的字段推断。即使知道一台台式机十有八九没有电池，也不写「无」——那是在替机器下结论。
- **并陈**：能算出两个真值（`512GB` / `476.9 GiB`）就都写出来，不替用户挑一个。

**为什么不做把关人。** 任何「这个字段在什么条件下不可信」的判断表都是**永久负债**：每加一条都要人来判断，而它一旦判断错，cowa 就从「信使说错了话」变成「把关人撒了谎」。信使的错误是**可归因的**——用户在别处一查就知道是 WMI 的锅；把关人的错误是**不可归因的**——用户会以为那就是真相。cowa 选前者，宁可显示一个明显可疑的数字，也不显示一个被我们修改过、看起来可信的数字。

## 边界：只筛实例，不改数值

`照抄` 管的是**值的真伪**，管不着**哪些设备实例算数**。多值行（显卡 / 显示器 / 声卡 / 网卡 / 磁盘）只列**物理设备**——`PNPDeviceID` 以真实总线前缀开头的那些（白名单）。这台机器上 19 块网卡因此变成 1 块。

这条边界不是「顺手优化」，是实测逼出来的：字面执行 `照抄` 会让屏上出现 **19 行网卡**、3 个显卡（含华为的 `Virtual Display Device`）、3 个显示器条目。

两个被实测否决的替代方案：

- **让微软判断**——`Win32_NetworkAdapter.PhysicalAdapter` 实测返回 **4** 块，把 Hyper-V 虚拟交换机算作物理，比白名单更差。「让系统替我们判断」这条路走不通。
- **坏前缀黑名单**——每撞到一个新虚拟设备就得补一条，`INDIRECTDSP\` 已经在欠账。

选**白名单**（只认好前缀）而不是黑名单：默认排除未知，新出现的虚拟设备不会溜进来；代价是将来某种新总线上的真实设备会被默默漏掉。

**后果（重要）。** 这会带来一批**永远不修的**"bug"报告：显存数字不对、台式机上电池显示 `未知`、硬盘容量写着两遍。**它们不是 bug，是这条决定的可见形态。** 想改回把关人，那是换产品，不是修 bug。
