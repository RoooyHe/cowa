# 精选装机方案在启动时取一次就冻结；取不到就是空

与 `ADR-0001` 一致：装机方案在**进程启动时取一次**，之后冻结——不轮询、不刷新、不重试、不缓存到磁盘。来回切 `标签栏`，内容不会变，也不会重新拉。

取数失败、超时、或返回空表，屏上**都是空的**：不写 `未知`（那是本地采集「这台机器没有 / 读不到」的语义，与网络无关），不给「加载失败」文案，也不区分「网络断了」与「没有方案」。信使不为空缺编故事。

**与 ADR-0001 的关系。** 这不是推翻，是**扩展**：不轮询仍然成立。ADR-0001 讲的是「启动快照」，这里只是给快照多接了一个远端数据源。

## Considered Options

- **首次切到该屏时才取 / 每次进屏都取**：否决——前者让「启动」不再是唯一的取数时机，后者就是轮询的网络版，两者都破 `ADR-0001` 的语义一致性。
- **磁盘缓存 + TTL，离线看上次的方案**：否决——引入持久化状态，第一次出现「上次的」与「现在的」之分；cowa 目前没有任何持久化。
- **手动刷新按钮**：否决——被零交互挡住（`ADR-0005` 的原意，今见 `ADR-0007` 的收窄）。

## Consequences

- 启动时断网 = 这一整轮看不到方案，只能重启。这是有意的代价。
- `硬件概览` 永不因网络失败而变化；远端取数与本地采集是**并行、独立**的两条路径。
- 第二屏**不设 `骨架`**：`固定图纸` 能骨架化是因为 `硬件概览` 的槽位数固定（12 个），而方案的**条数本身是数据**——无法预画未知张数的卡片。取数期间该屏即空。
