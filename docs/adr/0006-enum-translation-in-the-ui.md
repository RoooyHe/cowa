# 枚举翻译在 UI 侧，契约里带枚举结构

WMI 把枚举给成裸数值（`SMBIOSMemoryType = 26`、`PCSystemType = 2`）。`枚举翻译` 是必做的——不翻的话值根本无法阅读，屏上也不许出现裸数值。这条决定的是**在哪一层翻**，以及为了能翻，契约要长什么样。

**决定：采集侧只吐原始枚举值，翻译在 UI 侧查表。** 契约里新增第四种值形态——组合值 `parts`：一段固定文本 + 若干段，段要么是 `text`，要么是 `{ kind: "enum", table, code }`。`table` 目前只有 `memoryType` 与 `systemType`，表在 `src/hardware/enums.ts`。查不到表项的 code 写 `未知`：我们没拿到一个读得懂的值，而裸数值绝不能上屏。

**为什么。** 唯一的缝是 `FieldUpdate` 流（`issue #1`「唯一的那条缝」）。要让「喂数值 `26`，屏上是 `DDR4`」这条能在没有 Windows 的机器上测，翻译就必须在缝之上——组件收到的是结构，翻是组件的事。表在采集侧或 Rust 侧都测不了：那两处进不了前端的测试环境。反过来，这也让采集侧更贴 `照抄`：它原样转达 WMI 给的东西，不做任何解释。

**边界。** `PNPClass = MEDIA` 决定一个设备归到哪一行，是**分类**，留在采集侧；它不是值翻译。`厂商代码表`（`CMN` → `奇美`）仍然不做——那属于「翻译只为了好看」。

**代价。**
- 契约从 issue #1 画的三种形态变成四种。这是有意的收紧：三种形态里没有一个能同时承载「固定文本 + 需翻译的枚举」。
- 新增一种枚举 = UI 侧加一张表（+ 采集侧吐一个新的 `table` 名）。
- 查不到的 code 是 `未知` 而不是裸数值，这在本文件里被记进 `枚举翻译`。

## Considered Options

- **在 PowerShell 里拼好 `DDR4` 再吐字符串**：契约保持纯文本，最省事。**否决**——翻译规则就落进了没有测试环境的那一侧，`喂 26 → DDR4` 的 UI 测试无从写起。
- **在 Rust 反序列化时翻**：同样能测（`cargo test`），但那是另一条测试面，`issue #4` 要的是 UI 测试；而且它把「怎么说话」埋进了传输层。
- **查不到就照抄裸数值**：直接违反「屏上不出现裸数值」。**否决**。
