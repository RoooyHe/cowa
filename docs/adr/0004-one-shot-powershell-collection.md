# 采集走一次性 PowerShell 子进程

硬件概览的全部采集由**一个** PowerShell 进程完成：Rust 侧 spawn 一次，脚本把全部字段作为 JSON 吐到 stdout，Rust 反序列化后交给前端。没有 Rust 侧的 `wmi` crate，也不按字段起进程。

**为什么。** 实测硬数字：`pwsh` 冷启动 + 3 个查询 = **1701 ms**（`powershell` 5.1 = 2118 ms）。逐字段起进程不可能——这台机器单是网卡就 19 个实例。一个进程包办全部 ≈ 1.7 秒固定开销 + 查询时间，总计约 **2.5–3 秒**。而进程内直查（省掉那 1.7 秒）这条路的 `wmi` crate 是社区维护的依赖，**我们没有任何实测数字**。

**代价。**
- 依赖 PowerShell 存在（优先 `pwsh`，退回 `powershell` 5.1 再多约 0.4 秒）。
- 一次 2.5–3 秒的等待——由 `骨架` 兜住（图纸瞬间出现、格子逐个填满），不是黑屏。
- Rust 与 PowerShell 之间多一份 JSON 契约，两边都要维护。

**待办。** P2（Rust 进程内直查 WMI）**单独立项实测**。如果那 1.7 秒确实能省掉、且 `wmi` crate 够稳，这条 ADR 就该被取代。在那之前不要动。
