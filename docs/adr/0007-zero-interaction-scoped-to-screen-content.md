# 零交互收窄到硬件概览的内容；外壳的标签栏是例外

`硬件概览` 的**内容**上仍然没有任何可点元素：没有刷新、没有设置、没有右键菜单、没有主题开关。这一条没有变——变的是它的**作用域**。

`ADR-0005` 把「零交互」定为整个应用的性质，并把「导航壳」当作不存在的需求挡了回去（原话：第 2 屏还不存在，不为一个不存在的需求付税）。第 2 屏（`精选装机方案`）现在真的存在了，`标签栏` 因此必须存在。本 ADR **取代 `ADR-0005`**，把零交互从「整个应用」收窄为「`硬件概览` 的内容」。

**决定。** `应用外壳`（目前就是底部悬浮的 `标签栏`）是全应用**唯一**允许有可点元素的地方。`硬件概览` 屏的内容里一个可点元素都不许有；第二屏的内容里 V2 也不放可点元素。`ADR-0005` 的论证依然成立——「零」一旦开口就会滑坡——所以口子只开在**外壳**这一个地方，且只有两个标签。

**守卫测试要跟着改。** `src/hardware/zeroInteraction.test.tsx` 现在扫的是**整个 `src/`**（任何 `<button>`、`onClick`、全局键盘监听都会红）。它必须改成两件事：DOM 断言**只针对 `硬件概览` 的内容容器**；源码扫描**放行外壳**（`标签栏` 所在文件），但屏内容仍全禁。

## Considered Options

- **不改 0005，把标签栏画在窗外 / 用系统托盘切换**：否决——用户要在同一窗口里切屏，这是最直接的做法。
- **让 `硬件概览` 也带导航控件**：否决——导航属于外壳，不属于屏。屏的内容保持零交互。

## Consequences

- 「零交互」不再是全应用戒律，而是 `硬件概览` 定义的一部分（`CONTEXT.md` 已同步）。
- 想加第二个外壳控件，得先过这一关：为什么它不是「第一个按钮」滑坡的下一格。
