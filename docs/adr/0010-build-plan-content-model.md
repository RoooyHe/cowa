# 装机方案的内容模型：固定分类、管理员定序、与本机无关

一条 `装机方案` ＝ 名称 ＋ 一句介绍 ＋ 档次 ＋ `参考价` ＋ 一列固定分类的部件。分类**固定**（同 `固定图纸`）：CPU / 主板 / 内存 / 显卡 / 硬盘 / 电源 / 机箱 / 散热，外加一个 `辅助配件` 空列，收定制线、副屏这类落不进前面分类的东西。每格是管理员键入的自由文本，可以为空。方案在列表里的顺序由管理员的排序字段决定——没有点赞、没有投票、没有算法排名（`精选` 即主观挑选）。

**边界一：与本机无关。** 方案描述「可以怎么装」，不描述「这台机器是什么」。cowa 不拿用户现有硬件去匹配方案、不标「你已有 / 你缺」。

**边界二：`参考价` 是编辑内容。** 它是管理员录入时键入的**数字**（可空），不是 cowa 维护的实时市价。cowa 照抄（`照抄` 立场），不校正、不更新；配合 `ADR-0009` 的一取即冻，它在一轮运行里绝不会变。

## Considered Options

- **自由填写的方案（每条自定分类）**：否决——方案之间不可比、排版对不齐，`固定图纸` 的收益全丢。
- **精确价格**：否决——价格会馊、要人持续维护；用 `参考价` 加 `档次` 表达量级即可。
- **把本机配置与方案做匹配 / 推荐**：否决——把「目录」变成「推荐引擎」，是另一个产品。

## Consequences

- 空部件分类在屏上**不出现**。这与 `硬件概览` 的「不隐藏该行」相对：那条规则来自 `未知`（读不到 ≠ 没有），而方案缺一件就是**没配**，没有「不知道」可言。`辅助配件` 同理——没填就不显示。
